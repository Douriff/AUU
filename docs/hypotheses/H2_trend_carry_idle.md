## 2. 冻结参数（和报告、research2 代码一致）

### 趋势腿：B058，对应 `strat.trend_targets(sig="agree3", pvt=0.15, ccap=0.10, regime="zero")`
- **股票池**：19 币，BTC ETH SOL XRP DOGE BNB ADA AVAX LINK LTC TRX DOT BCH ETC XLM ATOM FIL UNI NEAR。
- **信号**：现货收盘价同时高于 20、60、120 天前的收盘价，才持有，且只做多。
- **单币仓位**：min(0.25 / 90 日年化波动, 2.0) / 合格币数。合格 = 现货和永续连续 90 天都有数据。
- **牛熊过滤**：BTC 现货收盘价 ≤ 200 日均线时全部清仓。
- **组合波动目标**：用过去 60 天日收益（缺失按 0）的样本协方差，算出当天持仓的事前年化波动，把仓位缩放到 15%。缩放倍数上限 10 倍，总敞口上限 2.0。
- **单币上限**：每个币的权重最多 10%。
- **执行**：AUU `engine.step`，再平衡带宽 20%，最小交易 1%。
- **成本**：AUU `CostModel`。吃单费 0.05%，加滑点 BTC/ETH 1bp、SOL/XRP/DOGE/BNB 2bp、其他币 3bp，按单边计。资金费用行情库里的实际数据，多头付。
- **盈亏价格**：行情库的永续收盘价。目前行情库用现货收盘价代替，和 trend_tsmom_v1 纸面策略相同。

### 套利腿：funding_arb Book A，对应 `fa_backtest.sim_A(mode="always", L=3)`
- BTC 和 ETH 各 50%，常开。现货做多加永续做空，永续 3 倍杠杆，保证金 = 名义 / 3。
- **费用**：现货吃单 0.10%，永续吃单 0.05%，滑点每边 1bp。
- **爆仓判断**：维持保证金率 0.5%，用当日永续最高价检查。
- **再平衡**：永续权益低于初始保证金的 50%，或高于 200% 时，把两条腿调回目标。
- **日线步进**：现货收盘价来自行情库；永续收盘价和最高价来自交易所公开 1d K 线，抓到后存进 `shadow_h2.sqlite`；资金费 = 当日各次结算之和，来自行情库。

### 闲置资金
- 趋势腿里没有用于持仓的资金，即 max(0, 1 − 持仓总敞口)，按 **3.99%/年** 计息。
- 这和 research2 stage3 的 `cash_yield=TBILL`、AUU `stats.TBILL` 一致。
- **收益假设和来源**：3 个月 T-bill 3.99%，和 AUU 的基准常数相同。现实中更可能拿到的是 sUSDS（约 3.6%，DefiLlama 池 `d8c4eff5-…`）或交易所理财，会带来托管风险或合约风险，所以 3.99% 偏乐观（见 §6）。

### 两条腿的组合
- **权重**：按 60 日波动的倒数分配（风险平价）。在每月第一个 UTC 日收盘时重新分配，挪动的资金按 0.17% 收成本。
- **零波动处理**：如果某条腿过去 60 天的波动 ≤ 1e−12，它拿 100% 权重。这是波动倒数在波动趋于 0 时的极限，比如趋势腿空仓、只拿闲置收益的时候。research2 的 pandas 实现在这种情况下给出约 0.99999。两条腿都为 0 时各 50%。
- **起始**：2026-10-04（UTC）收盘建仓，名义 10,000 USDT（不是真钱）。首日只记建仓成本。开头需要的 60 日波动窗口，用同一套代码在行情库历史数据上重建（`warmup` 表）。

### 基准
- T-bill 3.99%/年（常数）。

## 3. 事先定好的通过门槛（唯一判定标准）
- **样本**：起始日（含建仓成本）加之后连续 **180 个 UTC 日**，即 2026-10-04 到 2027-04-02，共 181 行。
- **统计量**：`stats.summarize` 的 `excess_ci`，即年化日均收益减 T-bill 的 95% 区间。用移动块 bootstrap，块长 20 天，重抽 2000 次，随机种子 `StdRng(7)`。
- **通过**：超额收益 CI 下限 > 0，并且没有触发任何中止条件。否则判失败。
- 第 180 天的数据记完后（约北京时间 2027-04-03 08:15）自动评估一次，只评估一次，结果写入 `evaluations` 表。
- 不提前判通过。不足 180 天的累计数字只用来记录，不算证据。

## 4. 失败和中止条件（事先定好）
| 条件 | 结果 |
|---|---|
| 组合净值从高点回撤 ≤ −5%（留出期最大回撤约 −0.6% 到 −1.3%） | 中止，结论锁定为**失败**（记录 `events` / `meta.aborted`） |
| 套利腿任何一个币发生爆仓（留出期 0 次） | 中止，判**失败** |
| 参数、成本模型、T-bill 常数或登记文件的哈希对不上 | **拒绝运行**；如果是有意修改，H2 作废 |
| 影子计算落后超过 7 天 | 暂停，标记 `paused`，需要人工检查 |
| 落后超过 30 天还没补上 | H2 **作废** |
| 一次补算超过 10 天 | 不自动补，需要人工检查 |

中止之后可以继续记录，但结论不再改变。

## 5. 运行方式
- **模块**：`app.paper.shadow_h2`。API 进程里每 5 分钟检查一次，开关是 `AUU_SHADOW_H2`，默认 on。
- **计算时间**：UTC 日 D 收盘后满 15 分钟（北京时间 08:15 起），并且满足以下条件后，计算 D 收盘时的目标仓位和模拟净值：
  - 08:00 的纸面调仓已经写入 D，或者收盘已过 60 分钟；
  - 行情库里 D 的数据齐全。
- **只写** `data_dir()/shadow_h2.sqlite`，不打开、不写任何纸面账本。不下单。
- **记账**：三条腿分开记。
  - 每日 `pnl_trend`、`pnl_idle`、`pnl_carry`、`cost_sleeve`（单位 USDT），满足 nav_t − nav_{t−1} = 三条腿之和 − 腿间调仓成本；
  - 每日还记录两条腿各自的收益、权重、趋势目标仓位、套利状态。
- **查看**：
  - 登录后 `GET /api/v1/mainstream/shadow/h2`；
  - 每日 08:30 摘要邮件里有一行 H2；
  - `python -m app.paper.shadow_h2 hash|preview|status`，其中 preview 在内存里做一次完整的起始计算，不写任何文件。

## 6. 已知差异和局限（登记时已经写明）
- **回放核对**：在 research2 的 Binance 归档面板上回放 2025-01-08 → 2026-09-30 的结果见下表。
  - 套利腿用日线步进，research2 用的是小时级 `sim_A`。
  - research2 的 `sim_A` 在加仓再平衡时按带符号的 dq 计费，所以加仓反而“返还”手续费。这里改为 |dq|，手续费永远不会是负数，结果更保守。

| 回放版本 | 年化 [CI] | 超额 CI |
|---|---|---|
| 本实现 | +5.12% [+2.98, +8.50] | [−1.01, +4.51] |
| 改回带符号计费 | +5.23% [+3.09, +8.58] | [−0.90, +4.59] |
| research2 报告 | +5.24% [+3.12, +8.59] | [−0.87, +4.60] |

  - 结论：两者的差别几乎全部来自这个计费 bug。趋势腿和 research2 逐日一致（最大差 4e−16）。
- **熊市阶段的收益结构**：2026-01 到 2026-08，BTC 低于 200 日线，趋势腿空仓，组合约 100% 放在趋势腿的闲置资金上，收益就是 T-bill。所以熊市阶段的超额收益天然接近 0，前向 180 天能不能通过，主要取决于牛市阶段的趋势和套利表现。
- **价格数据**：行情库的永续价格用现货代替（趋势腿）。套利腿的永续价格来自交易所公开 K 线，东京服务器用 Binance，box 上会回退 OKX。每行都记录了交易所。
- **闲置收益假设偏乐观**：按 T-bill 全额计息；sUSDS 约 3.6%，并且有合约风险。
- **样本太短**：180 天的 CI 会比较宽，通过门槛偏严，这是有意设计的。
