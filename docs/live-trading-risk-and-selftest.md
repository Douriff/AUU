# 实盘风险说明与小额自测计划

> 适用范围：「资产/盈亏」页的「实盘」视图（`/pnl?view=live`），以及它调用的「交易所接入」下单端点（`/api/v1/exchange/*`）。
> 对象：站长/运维（上线前评估、应急）和第一批内测用户（自测）。
> 一句话：**实盘下的每一笔单都是真钱，由用户自己点击并二次确认；策略永远不会用用户的 Key 自动下单；总开关默认关闭。**

---

## 1. 这个功能做了什么、没做什么

| 做了 | 没做（也不会做） |
| --- | --- |
| 页面上「纸面｜实盘」切换；实盘视图展示用户**自己绑定**的币安/OKX 现货余额、U 本位永续持仓 | 策略/机器人/定时任务用用户 Key 自动下单（代码里没有这条路径，并有单测守住） |
| 现货买入/卖出（含「卖出全部」）、合约开仓、合约平仓（reduce-only 市价） | 提现、划转（绑定时就拒绝带提现/划转权限的 Key） |
| 每笔订单二次确认弹窗：交易所、品种、方向、数量、预估成交价、杠杆/保证金模式 | 币本位合约、交割合约、杠杆现货/借贷、期权 |
| 服务端再次校验：总开关/白名单/紧急停止/Key 权限/品种/金额/杠杆/确认标记 | 在前端"藏按钮"当作安全措施——前端只是展示，后端才是闸门 |
| `clientOrderId` 幂等 + 3 秒相同订单去重，防双击/重放 | 价格保护（滑点上限）：市价单以交易所撮合为准，见风险点 R3 |

## 2. 风险点清单

| 编号 | 风险 | 说明 | 现有缓解 | 剩余风险/建议 |
| --- | --- | --- | --- | --- |
| R1 | **资金损失（本质风险）** | 加密资产价格剧烈波动；合约有杠杆，逐仓可被强平，全仓可连带其它仓位 | 默认总开关关闭 + 白名单；单笔名义上限（`maxOrderUsdt`/`maxFuturesUsdt` 默认各 50 USDT）；杠杆上限（`maxLeverage` 默认 5）；每笔二次确认；首次用合约需单独确认风险 | 首批只给小额；上限由站长调整，不建议一开始放大 |
| R2 | **Key 泄露** | 数据库或服务器被攻破，用户 Key 被拿走 | 仅接受无提现/划转权限的 Key；AES-256-GCM 信封加密，每条凭证独立 DEK，AAD 绑定 用户+交易所；主密钥只在服务器环境变量；Key 必须配 IP 白名单（只允许本站出口 IP）；日志/审计不含明文 | 即使泄露，攻击者仍可在白名单 IP 之外无法使用；仍建议用户给 Key 设置"仅交易、不提现"并随时可在交易所吊销 |
| R3 | **市价单滑点/成交价偏离** | 弹窗里的"预估成交价"取自交易所当时盘口，成交可能不同；薄品种尤甚 | 只允许交易所列出的、状态活跃的 USDT 品种；单笔上限；限价单可选 | 弹窗价是**预估**；大额/薄品种请用限价单 |
| R4 | **重复下单** | 双击、网络重试、页面刷新 | 弹窗打开时生成一个 `clientOrderId`，提交期间锁按钮；服务端对同一 id 只执行一次；结果未知（超时）时用同一 id 去交易所**查询**而不是重发；另有 3 秒内相同订单去重 | 用户在两个设备上各点一次属于两笔不同订单（不同 id），会被 3 秒去重挡住或各自执行——请只在一处操作 |
| R5 | **结果未知（超时）** | 请求发出后网络断开，不知道有没有成交 | 订单记为 unknown；页面提示"用同一笔订单重试查询"；再次提交会按 `clientOrderId` 查询，不会重发 | 重试前也可直接到交易所 App 核对 |
| R6 | **合约平仓方向/数量错误** | 手工反向单会变成反向开仓 | 平仓端点**不接收**方向和数量：由服务端从交易所读取持仓，自动取反向并带 `reduceOnly`；对冲模式下多空两腿都会平 | 平仓前会读持仓，若已被强平/已平则返回 `NO_POSITION`，不下单 |
| R7 | **强平风险** | 逐仓保证金耗尽或全仓整体亏损 | 杠杆上限；持仓表展示强平价、杠杆、保证金模式 | 本功能不自动补保证金、不自动止损；请自行在交易所设置 |
| R8 | **紧急停止后的处置** | 出事时需要快速止血 | 紧急停止：阻止所有新开仓和现货下单，但**合约 reduce-only 平仓、撤单仍可用**，让用户能减风险；管理员可对单个用户一键平掉全部合约仓位并撤单 | 紧急停止不会替用户平仓；如需代平，用管理端 close-all（会写审计） |
| R9 | **交易所侧变化** | API 变更、品种下架、限频、维护 | 品种每次下单前再校验；限频与交易所错误有明确提示；错误不会被当成成交 | 需要持续关注 ccxt 升级与交易所公告 |
| R10 | **合规/ToS** | 代客操作、地区限制、牌照 | 仅"用户自带 Key、用户自己点击"；站点不托管资金 | 站长自行评估所在地区的合规要求，见 `docs/exchange-api-integration.md` §8 |
| R11 | **双节点/备机** | 备机误写 | standby 节点拒绝 `/api/v1/exchange/` 下的所有写操作，视图显示"不可用：备用节点" | 切主前确认主密钥在新主机上可用 |
| R12 | **OKX 张数单位** | OKX 永续按"张"计量（BTC 1 张 = 0.01 BTC），容易按币数下错 | 票据区提示"OKX 数量单位为张"，弹窗里的名义价值按合约面值折算后显示 | 首次在 OKX 自测时务必只下 1 张 |

## 3. 「不可用」状态一览（界面灰掉并写明原因；后端同样拒绝）

| 状态码 | 界面文案（简） | 触发条件 | 用户怎么办 |
| --- | --- | --- | --- |
| `EXCHANGE_OFF` | 实盘总开关未开启 | 管理端 `enabled=false`（默认） | 等站长开启 |
| `EXCHANGE_NOT_ALLOWED` | 账号未在内测名单 | 白名单模式下账号不在名单 | 联系站长 |
| `NOT_BOUND` | 还没有绑定这个交易所的 Key | 未绑定 | 去「交易所接入」绑定 |
| `KEY_NO_TRADE` | Key 没有现货交易权限，只能查看 | 只读 Key | 在交易所给 Key 开"现货交易"后重绑 |
| `KEY_NO_FUTURES` | Key 没有合约交易权限 | 未开合约权限 | 开权限后**解绑再重绑**（权限在绑定时检查） |
| `FUTURES_ACK_REQUIRED` | 先确认合约风险提示 | 首次用合约 | 去「交易所接入」阅读并确认 |
| `KEY_HAS_WITHDRAW` | Key 带提现权限，已拒绝 | 绑定时检测到 | 重建一把无提现权限的 Key |
| `KILL_SWITCH` | 管理员已紧急停止 | 站长开启紧急停止 | 现货与合约开仓暂停；合约可平仓 |
| `STANDBY` | 备用节点不可写 | 访问到备机 | 等切回主节点 |
| `CRYPTO_UNAVAILABLE` | 服务器加密密钥未配置 | 主密钥缺失 | 联系站长 |
| `SYMBOL_UNSUPPORTED` | 交易所不支持该品种 | 品种未上市/已下架/不是 USDT 现货或线性永续 | 换品种 |

## 4. 站长上线前检查（只在你确认要放给内测用户时做）

1. 服务器已配置 `AUU_EXCHANGE_MASTER_KEY`（`/etc/auu/auu.env`，32 字节 urlsafe base64），并**离线备份**；丢失则所有已绑定 Key 不可解密（用户需重绑）。
2. 管理端 `/admin/exchange`：`enabled=false` 起步；`allowlistOnly=true`；只加你自己和 1–2 个内测账号；`maxOrderUsdt`、`maxFuturesUsdt` 保持默认 50；`maxLeverage` 保持 ≤ 5。
3. 确认交易所 Key 的 IP 白名单填的是页面上显示的本站出口 IP（主/备两个都加）。
4. 先在**自己的**账号上完成第 5 节自测，再放第二个人。
5. 确认你知道关闭方式（第 6 节），并实际演练一次"开启紧急停止 → 页面变灰 → 关闭"。

## 5. 小额自测计划（用户/站长自己做）

> 原则：**用最小金额、先现货后合约、一次只改一个变量、每步都对照交易所 App 核对。** 不要用大额账户，建议用新建的子账户或只放少量资金（例如 30–50 USDT）。本流程不会、也不应该使用 Key 的提现权限。

### 5.0 准备

- [ ] 交易所账户里准备约 30–50 USDT（现货与合约账户分开放；合约测试再划转少量即可）。
- [ ] 在**币安**创建新 API Key：
  - 勾选：读取、现货交易（合约测试时再勾"合约交易"）；
  - **不勾**：提现、内部划转、万向划转；
  - IP 访问限制：仅限信任的 IP，填入页面「交易所接入」里显示的本站服务器 IP；
  - Key 备注写"AUU 小额自测"，方便日后吊销。
- [ ] 管理端已开启总开关并把你的账号加入白名单。

### 5.1 绑定与"不可用"状态验证（不花钱）

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 1 | 总开关关闭时打开 `/pnl?view=live` | 现货/合约区都显示"不可用：实盘总开关未开启"，下单/平仓按钮灰色不可点 |
| 2 | 开启总开关但不在白名单 | "不可用：账号未在内测名单" |
| 3 | 在白名单但未绑定 | "不可用：还没有绑定"，并有"去绑定"链接 |
| 4 | 先绑一把**只读** Key（不勾交易） | 能看到余额；下单区灰色，原因"Key 没有现货交易权限" |
| 5 | 尝试绑一把**带提现权限**的 Key | 绑定被拒绝（`KEY_HAS_WITHDRAW`） |
| 6 | 解绑，绑上第 5.0 的现货交易 Key | 实盘视图现货区"可用"，显示真实余额，与交易所 App 一致 |
| 7 | 合约区 | 显示"先确认合约风险提示"（`FUTURES_ACK_REQUIRED`）——此时合约不可用，符合预期 |

### 5.2 现货（先做）

| 步骤 | 操作 | 期望结果 / 核对点 |
| --- | --- | --- |
| 1 | 在现货票据区输入一个不存在或已下架的品种 | 立即显示"不可用：交易所不支持该品种"，按钮灰色 |
| 2 | 买入 BTC（或 ETH）**约 10 USDT 对应的数量**，**限价单**，价格设为明显低于市价（不会成交） | 弹窗显示：交易所=币安、品种、方向=买入、数量、类型=限价、杠杆处写"现货"；点确认后订单出现在「交易所接入」的挂单里；交易所 App 里也能看到 |
| 3 | 在弹窗点确认时**连点两次** | 只产生 1 笔订单（交易所 App 核对）；提交期间按钮被锁，重复请求在服务端按 clientOrderId 返回"重复/已处理" |
| 4 | 到「交易所接入」或交易所 App 撤掉这笔挂单 | 挂单消失 |
| 5 | 再下一笔**市价**买入，金额约 10 USDT（须不超过单笔上限） | 成交；余额出现该币；USDT 减少；估价与实际成交价偏差在合理范围 |
| 6 | 在余额表点该币的「卖出全部」 | 弹窗方向=卖出，数量=可用余额；确认后成交，币清零，USDT 回来（扣除手续费与价差） |
| 7 | 下一笔**超过单笔上限**的单 | 被拒绝（`ORDER_TOO_LARGE`），没有任何订单到交易所 |

### 5.3 合约（现货全部通过后再做）

| 步骤 | 操作 | 期望结果 / 核对点 |
| --- | --- | --- |
| 1 | 在 Key 上开启"合约交易"，**解绑并重新绑定**；再到「交易所接入」确认合约风险 | 合约区变为"可用" |
| 2 | 先在交易所 App 里把合约账户放入少量 USDT（例如 20 USDT） | 页面能读到持仓（此时为空） |
| 3 | 品种 BTC/USDT 永续，方向做多，**杠杆 1–2x，逐仓**，数量使名义价值约 10–20 USDT | 弹窗显示：交易所、品种、"U 本位永续"、做多、数量、预估价、**杠杆与保证金模式**；确认后持仓表出现该仓位，强平价、杠杆、模式与交易所 App 一致 |
| 4 | 尝试杠杆超过上限（接口直测或把上限改小后试） | 被拒绝（`LEVERAGE_TOO_HIGH`） |
| 5 | 点持仓行的「平仓」 | 弹窗标明"只减仓（reduce-only）"、方向与数量取自持仓；确认后持仓消失 |
| 6 | 在平仓弹窗里连点确认 | 只平一次；不会反向开仓（交易所 App 核对没有反向持仓） |
| 7 | 在已平仓后再次对同一品种平仓（刷新前点旧按钮或重放请求） | 返回"没有持仓"，不会开新仓 |
| 8 | OKX 重复 5.2–5.3，**数量用 1 张** | 票据区提示张数单位；弹窗名义价值按面值折算正确 |

### 5.4 紧急停止与应急（站长演练）

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 1 | 持有一个小额合约仓位；管理端开启 `killSwitch` | 现货下单与合约开仓按钮变灰并写"管理员已紧急停止"；**合约「平仓」仍可点** |
| 2 | 在紧急停止下平掉该仓位 | 成功（reduce-only 平仓不受停止影响） |
| 3 | 关闭 `killSwitch` | 恢复可用 |
| 4 | 再开一个小仓位，调用管理端 `close-all`（指定该用户） | 撤销合约挂单并平掉所有合约仓位；审计里有记录 |

### 5.5 通过标准

全部勾选通过，且**交易所 App 里的订单/持仓/余额与页面一致、没有任何重复或反向订单**，才放开第二位内测用户。任何一步异常：立即按第 6 节关闭，保留审计记录与 `clientOrderId` 交由开发排查。

## 6. 回滚与关闭方式（从轻到重）

| 级别 | 做法 | 效果 | 恢复 |
| --- | --- | --- | --- |
| L0 单次操作异常 | 到交易所 App 直接撤单/平仓（最可靠，不依赖本站） | 立即生效 | — |
| L1 紧急停止 | 管理端 `PUT /api/v1/admin/exchange {"killSwitch": true}`（或 `/admin/exchange` 页面开关） | 所有用户的现货下单、合约开仓被拒；合约平仓/撤单保留 | 设为 `false` |
| L2 关闭总开关 | 管理端 `enabled=false` | 全部实盘能力（含读取）显示"不可用：总开关未开启"，接口返回 `EXCHANGE_OFF`；页面的「纸面」功能不受影响 | 设为 `true` |
| L3 单个用户 | 从白名单移除，或管理端对该用户 `close-all` 先平仓 | 只影响该用户 | 重新加入白名单 |
| L4 用户自行解绑 | 「交易所接入」页点"解绑"（删除服务器上的加密 Key）；并在交易所**删除这把 API Key** | 本站再也无法用该 Key | 重新绑定 |
| L5 代码回滚 | 回滚本功能的合并提交（后端新增接口、前端实盘视图均在同一 PR 内；`/exchange` 旧页与旧接口兼容）；回滚后总开关仍为关闭状态 | 实盘视图消失，纸面平仓（阶段 A）可单独保留 | — |

> 紧急情况优先顺序：**交易所 App 手动处理 → 紧急停止 → 关总开关 → 吊销 Key。** 任何时候都不要为了"恢复"而临时放开提现权限。

## 7. 已知限制

- 市价单的预估价只是盘口快照；成交价以交易所为准。
- 现货"平仓"= 市价卖出该币的全部可用余额（不处理冻结在挂单中的部分，需先撤单）。
- 余额与持仓每 15 秒轮询，不是实时推送；下单后页面会立即刷新一次。
- 目前不做自动对账与交易所 WebSocket 推送；没有页面内的止盈止损（合约票据区不带 TP/SL，请到交易所设置）。
- 本功能的自动化测试全部使用 mock 交易所客户端，**从未连过真实交易所**；真实环境行为必须靠本文第 5 节的小额自测验证。
